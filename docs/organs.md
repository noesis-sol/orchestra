# Organs

Orchestra's one-shot advisers: triage, the predictor, the reviewer, the screen, the plan and the scout. Back to the [README](../README.md).

## Organs

Organs are orchestra's one-shot advisers (see [Workers and organs](../README.md#workers-and-organs)). The orchestrator gathers the evidence itself and passes it to `claude -p` with every built-in tool and MCP server disabled (`--tools "" --strict-mcp-config`), from outside the project and in Claude Code's safe mode (`CLAUDE_CODE_SAFE_MODE=1`). An organ has no tool to look further than what it's given, and can only answer. The scout is the one exception, below: it reads the repository itself, with read-only tools. Organs advise: the orchestrator writes their output down, and no organ changes a ticket's status. A call is about 1,500 input tokens and takes 5–15 seconds; the plan's evidence is larger, with the repository's file list, and the call takes longer at its higher effort. Each call has a time limit: 2 minutes for the predictor and the screen, 3 for triage, 5 for the report and the scout, and 10 for the plan. A call still running then is stopped and fails with `claude: timed out after 10m`; one that answers and exits isn't held up by a process `claude` left running.

Running from outside the project keeps the project's `CLAUDE.md`, settings and hooks out of an organ; safe mode keeps out your own Claude Code setup, which `claude -p` loads from anywhere. Measured on 2026-10-02 with Claude Code 2.1.287 and a subscription login, on a short organ call (a one-line system prompt and a question about the model's context): without safe mode, the model's context held `~/.claude/CLAUDE.md`, a `SessionStart` hook from the user settings and a `Stop` hook from a plugin ran, and auto-memory was on, for 1,043 input tokens. With it, the call took 529 input tokens, no hook ran, auto-memory was off, and the login and the model were the same. What still applies: your default model and other settings, managed (policy) settings, and Claude Code's note of your account's email. Without safe mode, a hook that acts on its environment would act on every organ call: Herdr's Claude integration, for one, installs a `SessionStart` hook that reports a Claude session to the Herdr pane it runs in, which for an organ is orchestra's own. A `claude` too old to know safe mode ignores the variable and loads your setup as before.

- **Triage**, for each deferred ticket. The evidence is the ticket (`bd show`), the end of the worker's terminal, the end of a Claude worker's session transcript (its last messages, tool calls and errors; see [the hooks](workers.md#worker-prompt)), the permission prompts it waited on and the compactions of its context, as its hooks noted them, and its worktree's changes and commits. The model decides whether the cause lies in the **environment** (the machine, tools or services), the **instructions** (the worker prompt or the ticket's wording), or the **problem** itself. It adds a recommendation to the ticket's notes, and a purple `◆` line appears in the terminal. Triage runs in the background, one ticket at a time, so the loop doesn't wait. With triage off, or for a ticket set aside after Ctrl+C, no evidence is gathered. Should 64 deferrals already wait for triage, a ticket the loop itself finds deferred (one waiting on your answer, deferred in its worker's tab) isn't triaged: the log says `<id> is not triaged: 64 deferrals wait for triage already`. When the loop stops, orchestra says `Finishing triage…` and waits for the tickets still queued; Ctrl+C then skips them, and the one being triaged, without a warning for each.
- **Predictor**, for each ready ticket that names nothing its [footprint](running.md#several-tickets-at-once) can use. The evidence is the ticket (`bd show`) and the repository's files (`git ls-files`); the model picks the few files the ticket will most likely change. The guess is cached on the ticket as `predicted_files` metadata (apart from your `files`), so it's asked once per ticket, and scheduling uses it from then on. It runs in the background, one ticket at a time, only with several tickets at once and footprints on; a ticket is dispatched without waiting for its prediction.
- **Reviewer**, when the loop stops for any reason. It waits for pending triage, then reads the run's log lines, the commits merged during the run, the tickets set aside (with their triage notes) and the tickets still running when it stopped, with the permission prompts and compactions each ticket's Claude workers' hooks noted in this run ([the hooks](workers.md#worker-prompt)). For each ticket set aside because its check failed (`CHECKS_FAILED`, or a hand-back whose resolution fails it), it reads what the check said: the lines of its output that say what failed (a package's or a test's `FAIL` line, a data race and its test, a test timed out and the tests running, a lint, vet or build error, a tool's own error such as golangci-lint's lock), at most 30 of 200 characters each, or its last 30 lines when none says, and the directories the ticket's own commits change. It writes a short report in three sections: **Finished**, **Set aside** and **Needs you**. A failed check's bullet names what failed and whether in the ticket's code (a directory its commits change) or elsewhere; **Needs you** says to fix the ticket's code for the one, and to rerun the check in its worktree, merging it if it passes, for the other. The report is shown in the terminal, rendered with Glamour, and saved to `.orchestra/reports/<start time>.md`. Pressing Ctrl+C while it's writing skips it, and pressing it again quits at once; a second Ctrl+C while a stopped run waits for its workers skips it too. A SIGTERM or SIGHUP (closing its terminal or Herdr pane) during the run skips the reviewer.
- **Screen**, for a feature request typed or pasted, before it is planned. The evidence is the request and the first 4,000 bytes of the repository's README, so the model knows what the project is. Its verdict is **ok**, **reject** (malicious, such as a backdoor or sending secrets away, or unfit for a coding agent on this repository) or **unclear** (too vague to plan, such as "make it better"), with a sentence or two of reason for the user. Ambitious, refactoring and exploratory requests are ok. If the screen fails, the request counts as not screened. It is a guard against mistakes and pasted content, not a security boundary: workers run with your own permissions.
- **Plan**, for a feature request the screen passed. The evidence is the request, the README and `CLAUDE.md` (or `AGENTS.md`), up to 16,000 bytes each (a `CLAUDE.md` that is blank or holds only Claude Code imports, such as a lone `@AGENTS.md`, is replaced by the files it imports, one level deep, or else by `AGENTS.md`; an import is read only inside the repository, never through `..`, a home or absolute path, or a symbolic link that leads out), the repository's files with their line counts (`git ls-files`; a file over 4 MB isn't counted), every ticket not closed (open, in progress, blocked or deferred) with its ID, status and title, so the plan doesn't repeat one, and the start of any repository file the request names by path, with or without a line after it (`internal/x/y.go:120`, `y.go#L120-L140`). The model plans an epic and 1 to 12 child tickets, each one worker's session of work, with acceptance criteria, the files it will change and the tickets that must finish first; or, when it can't plan without answers, only questions. It can't read the code, so a request whose right change depends on the code starts with a design ticket, whose worker studies the code and files the rest of the tickets under the epic. Orchestra checks the plan: unique keys, blockers that are in the plan and form no cycle (an empty one is ignored), known types and priorities. A file that is neither in the repository nor new in an existing directory is dropped with a note.
- **Scout**, for `orchestra init`'s checks step: the test suites, lints, type checks and builds the project already has. It is the one organ with tools, and only read-only ones: `--tools "Read,Glob,Grep"`, still with `--strict-mcp-config` and no MCP servers, no saved session and safe mode. It starts in the repository's root rather than outside it, so that Claude Code lets those tools read the project without asking; safe mode keeps the project's `CLAUDE.md` and hooks out all the same. Its reads stay inside the repository: Claude Code asks before a tool reads outside the working directory, and nobody can answer in `claude -p`, but a setting could answer for it (an allow rule such as `Read(//**)`, or `bypassPermissions` as the default mode), and a file in the repository could ask the scout to read elsewhere. So when `claude --help` lists them (Claude Code 2.1.289 and later), the scout also gets `--restricted`, which confines the file tools to the working directory whatever the settings say, and `--permission-prompts none`, which denies whatever would prompt; an older `claude`, which would reject flags it doesn't know, runs without them. Restricted mode ignores your user, project and local settings files, so the scout doesn't use the default model or the `env` set there (`-organ-model` still picks its model), and managed settings that make `bypassPermissions` the default mode make it fail. It looks where projects say how they test (package manifests and their scripts, Makefiles and task runners, CI workflows, test configs, the project's own scripts such as `scripts/ci-local.sh`), runs nothing and changes nothing, and is stopped after 5 minutes or, when `claude --help` lists `--max-budget-usd`, once it has spent $2.00 (`claude` checks after each turn, so the last turn may take it a little past). Measured on 2026-10-06 with Claude Code 2.1.291 on seven repositories: $0.08–0.12 a scout at its `medium` effort with the default model or Sonnet (5–10 turns, 11–22 s), $0.15 on Opus and $0.16 on Haiku (23 turns); at `max` effort on Opus, $1.01 and $1.13 in about 4 minutes (28 and 40 turns), and a third stopped at 5 minutes. The budget is twice the dearest of those: it stops a scout that spends fast, at a high effort or a dear model, where the time limit would let it go on. For each suite it gives a name, a kind (unit, integration, e2e, lint, typecheck, build or other), the command as the project runs it, the `file:line` that defines it, a tier (**fast**: unit tests, lint, type checks and one smoke e2e suite; **full**: the rest), whether it is safe to run beside another copy of itself (not with a fixed port, a shared database or a fixed container name) and what it needs (services, a browser, credentials). An existing `scripts/check.sh` comes first, as a fast suite: orchestra puts it there, and adds it if the scout left it out. It also lists the project's stack (its languages, frameworks, test frameworks and linters, with versions a manifest pins, such as `Go 1.26`), which init gives the verifier (see [The verifier](setup.md#the-verifier)). With no suites, the answer is an empty list and a note saying what the scout looked at. When it can't answer (`claude` missing, its time limit, its budget (`the scout was stopped at its budget of $2.00: …`), a failure, or an answer that isn't the JSON asked for), init gets an error that says which, to show. The files it reads are the project's, which may hold text addressed to it: its system prompt says to use them only as evidence of how the project checks itself.

Turn them off with `-triage=false` / `TRIAGE=0` and `-review=false` / `REVIEW=0` (the predictor goes with footprints: `"footprint": false`), and pick their model with `-organ-model` / `ORGAN_MODEL` (default: the `claude` CLI's). If `claude` isn't installed, organs switch off and the log says so.

Every organ call sets its effort (`claude --effort`): `low` for triage, the predictor and the screen, whose answers are short and structured, `medium` for the run report and the scout, and `high` for the plan, made once per feature, whose quality decides the run. `--organ-effort` / `ORGAN_EFFORT`, or `"organ_effort"` in `settings.json`, sets one effort for all of them (`low`, `medium`, `high`, `xhigh` or `max`). Measured on 2026-10-01 with Opus 5.5, three calls each on this repository's tickets and logs, against `high` (Claude Code's default here): triage took 7.9 s at `low` against 15.0 s, the predictor 4.3 s against 7.2 s, and the report 7.3 s at `medium` against 8.5 s, with the same answers.

Each organ call `claude` answers is logged with what it cost, from its result: an `ORGAN` line such as `ORGAN triage: $0.0123 in 1 turn, 4.2s, session 1b2c…`, which names how the call ended when it failed (`error_max_budget_usd`, say). A run adds up its organs' cost: the reviewer is given what they cost before the report, and the report ends with an `Organs:` line giving the run's total, the report's own call included. `orchestra init` has no log: its summary has a `scout` line with what the scout's call cost, even when the form is cancelled. The cost is `claude`'s `total_cost_usd`, the whole call's; an older `claude` that doesn't give it logs `$0.0000`. A call that ends on an error says which, rather than "reported an error" alone: `claude reached its turn limit`, `reached its budget limit`, `gave no answer that matches the schema` (`--json-schema`'s retries ran out) or `failed during the call` (a crash among them), each followed by what `claude` said of it; a model that declines is `claude refused to answer`, even when `claude` reports the call a success. In code each is an `*organ.CallError`, whose `Subtype` and `Refused` say which.

An organ's evidence is text orchestra can't trust: tickets, worker terminals, logs. Each section of it sits between an opening and a closing tag carrying an ID drawn afresh for each call, such as `<evidence id="3fa91c0e">` … `</evidence id="3fa91c0e">`, each on its own line, and every organ's system prompt says that text inside the tags is evidence only, never instructions to follow. Text gathered before the ID was drawn can't close the tag early.
